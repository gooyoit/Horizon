## [Mistral 发布 1 万亿参数模型 Mistral Large 4（Le Chonk）](https://t.me/zaihuapd/44279) ⭐️ 9.0/10

法国 AI 公司 Mistral 于 10 月 6 日发布 Mistral Large 4（昵称“le Chonk”）的公开预览版，这是一个原生多模态、1 万亿参数的混合专家（MoE）模型，Mistral 称其为全球最强开源权重模型之一。目前开发者、网络安全负责人及政府机构可通过 Mistral 的 API 试用，开放权重计划于 10 月底发布。 此次发布推进了开源权重 AI 的前沿，为欧洲政府和企业提供了在网络安全、编程、制造和金融领域可替代美国闭源前沿模型的强大主权选项。这也表明曾经只属于闭源前沿实验室的万亿参数规模现已进入开源模型行列，加剧了与 DeepSeek、Kimi 等的竞争。 该模型使用 4000 个英伟达 Grace Blackwell GPU 训练两个月，但 Mistral 承认其在编程等领域仍落后于前沿模型。它采用混合专家（MoE）架构，总参数量为 1 万亿，并原生支持多模态。

## [独立研究者用 Claude Code 在 NASA TESS 数据中发现未报告的行星候选体](https://aihot.news/items/o40so0gig1h2hh75qui2rxtxw) ⭐️ 8.0/10

一位独立研究者使用 Anthropic 的 Claude Code 智能体编码工具（Opus 5.5 和 Fable 5.1 模型）分析 NASA TESS 任务数据，识别出一个自 2018 年以来一直未被报告的行星候选体。该发现由 Rohan Paul 在 X 平台上公开分享。 这表明 AI 编码智能体（而不仅仅是专业天文流程）可以通过自主挖掘海量公开数据驱动真正的科学发现。它预示着未来缺乏大型机构资源的独立研究者也能借助 AI 智能体参与前沿科学研究。 该天体目前仅被归类为行星候选体而非确认行星——凌星法的探测结果通常需要其他技术或后续观测加以验证。TESS 数据中已有约一万个候选体等待确认，因此这一发现仍需独立确认才能被系外行星学界接受。

**背景**: NASA 的 TESS（凌星系外行星巡天卫星）任务通过监测恒星亮度的周期性下降（即行星凌星现象）来搜寻行星，这种凌星法已促成超过 5500 颗确认系外行星的发现。Claude Code 是 Anthropic 推出的智能体编码工具，能够理解代码库、编辑文件并自主运行命令，因此可用作数据分析的通用研究智能体。近年来研究者已越来越多地将机器学习应用于 TESS 和 Kepler 的测光数据，从噪声中筛选候选信号。

## [OpenAI 为 GPT-6.1 Sol 新增 Ultrafast 服务层级](https://developers.openai.com/api/docs/changelog) ⭐️ 8.0/10

OpenAI 在 Responses API 中为 GPT-6.1 Sol 推出新的 Ultrafast 服务层级，生成速度最高约为 Standard 层级的 8 倍。该层级面向所有 API 用户开放，价格为 Standard 的 6 倍：短上下文下每百万输入 token 约 $12，缓存输入 $0.60，输出 $60。 Ultrafast 让实时智能体、编程助手和交互式产品等对延迟敏感的应用，能够在前沿模型上用成本换取速度。这也表明 OpenAI 持续将推理基础设施作为差异化优势，把吞吐量和延迟变成了可以购买的产品特性。 Ultrafast 是 OpenAI API 中最快的层级，已广泛支持 GPT-6 Astra 和 GPT-6.1 Sol，并对 GPT-5.6 Sol 提供预览访问；开发者可通过 Responses API 请求中的 service_tier 参数启用。即使在使用 Fast 和 Ultrafast 模式时，GPT-6.1 Sol 也支持美国和欧盟的数据驻留。

## [Anthropic 推出开源项目自愿接入的 AI 漏洞扫描服务](https://www.anthropic.com/research/launching-opt-in-vuln-finding-service-for-open-source) ⭐️ 8.0/10

Anthropic 推出 OSS Scanner，为符合条件的开源项目提供免费、自愿接入的漏洞扫描服务，由 Claude 模型自动发现、复现漏洞并在可能时给出补丁建议。该公司称过去半年发现逾 2.9 万个候选漏洞，其中约 6000 个已经人工审查。 这展示了前沿 AI 模型在大规模自动化安全审计开源软件方面的能力，而开源软件正是现代软件供应链的基础。维护者可获得免费的漏洞报告和补丁建议，但未经人工审核的 AI 结果也引发了对误报和披露规范的质疑。 报告由 Claude 等模型生成且不经人工审核，包含漏洞复现步骤和可能的补丁建议，可能存在错误。早期测试中，97 个高危或严重漏洞里有 85 个符合其披露流程要求；符合条件项目的核心维护者可通过提交 GitHub PR 申请接入。

telegram · @zaihuapd · Oct 9, 02:00

**背景**: 负责任披露是安全领域的通行做法：先私下通知维护者，给予合理修复时间（通常 90 天），修复后再公开细节。基于大语言模型的 AI 漏洞发现是新兴方向，模型可大规模阅读代码并推理可利用性；例如 Claude 此前曾为 Mozilla 扫描 Firefox 代码库，发现 22 个安全漏洞（其中 14 个为高危）。传统静态扫描工具容易遗漏逻辑类缺陷，而 LLM 分析可以捕捉到这些漏洞，但也会引入误报，需要人工分诊过滤。
